SwiftUI iOS 26 Showcase ist ein Swift-Paket mit sechzehn kleinen SwiftUI-Bildschirmen. Jeder davon
dreht sich um eine Gruppe von APIs, die mit iOS 26 und macOS 26 neu hinzugekommen sind: Liquid
Glass, die neuen Modifier für Leisten und Scrollen, Rich-Text-Bearbeitung, die native Web-View,
3D-Diagramme, Zeichen-Effekte für SF Symbols, das Makro `@Animatable` und das Framework Foundation
Models, das auf dem Gerät läuft. Jeder Bildschirm hat Bedienelemente, mit denen du die Optionen
der API ausprobieren kannst, und listet die SDK-Symbole auf, die er verwendet. Das Paket richtet
sich an Entwicklerinnen und Entwickler, die diese APIs in Aktion sehen wollen, bevor sie sie
selbst einsetzen: Du kannst die ganze Galerie starten oder einen einzelnen Bildschirm in deine
eigene App einbauen.

## Highlights

- **16 Demos in 6 Kategorien**: Liquid Glass, Leisten und Navigation, Scrollen und Layout, Text
  und Web, Diagramme und Symbole sowie Apple Intelligence. 14 davon laufen auch unter macOS.
- **Durchsuchbare Galerie**: `ShowcaseGallery` listet die Demos auf, die auf der aktuellen
  Plattform verfügbar sind; die Suche findet Titel, Zusammenfassungen und API-Namen.
- **Ein Bildschirm für sich**: `ShowcaseDemoView(.chart3D)` setzt eine einzelne Demo in deine
  eigene Navigation.
- **Getestet unter macOS und im iOS Simulator**: Suites mit Swift Testing prüfen den Katalog, die
  Hilfstypen und ob die Demo-Tabelle unten zum Code passt. Ein Rendering-Test prüft, ob jede Demo
  mehr zeichnet als ihre Zusammenfassung und API-Liste, soweit `ImageRenderer` sie zeichnen kann:
  Die beiden `List`-basierten Demos werden übersprungen, und in der **WebView**-Demo sieht der Test
  die Adress- und Statusleiste, aber nicht die `WebView` selbst.
- **Beispiel-App**: eine iOS- und macOS-App in [Examples/ShowcaseApp](Examples/ShowcaseApp), die
  jede Demo über ein Startargument öffnen kann.

## Schnellstart

**1. Paket hinzufügen**

Wähle in Xcode **File › Add Package Dependencies…** und gib die Repository-URL ein:

```text
https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git
```

Lass **Dependency Rule** im selben Dialog auf dem Standardwert **Up to Next Major Version** ab
`2.0.0` (das frühere Release 1.0.0 ist älter als diese Demos). Klicke auf **Add Package**, wähle in
der Spalte **Add to Target** das Target deiner App und klicke noch einmal auf **Add Package**.

**2. Modul importieren**

```swift
import SwiftUIiOS26Showcase
```

**3. Verwenden**

Ersetze den Inhalt der Hauptdatei deiner App (der Datei mit `@main`, die in einem neuen
Xcode-Projekt `<YourApp>App.swift` heißt) durch:

```swift
import SwiftUI
import SwiftUIiOS26Showcase

@main
struct DemoApp: App {
    var body: some Scene {
        WindowGroup {
            ShowcaseGallery()
        }
    }
}
```

Wähle als Ziel einen iPhone-Simulator mit iOS 26 oder **My Mac** und drücke **Run** (⌘R). Die
App öffnet eine nach Kategorien gruppierte Liste der Demos; wähle eine aus, um sie auszuprobieren.
Meldet Xcode, dass das Paket eine neuere Plattform braucht, setze im Tab **General** des Targets
**Minimum Deployments** auf iOS 26 und macOS 26.

## Installation

### Swift Package Manager

Wähle in Xcode **File › Add Package Dependencies…** und gib die Repository-URL ein:

```text
https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git
```

Oder füge es zu den `dependencies` in deiner `Package.swift` hinzu:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git", branch: "main")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "SwiftUIiOS26Showcase", package: "SwiftUI-iOS26-Showcase")
    ])
]
```

## Verwendung

### Die ganze Galerie zeigen

`ShowcaseGallery` ist ein Navigation-Stack mit einer durchsuchbaren Liste aller Demos, die auf der
aktuellen Plattform verfügbar sind. `ShowcaseGallery(initialDemo: .chart3D)` öffnet beim Erscheinen
direkt eine Demo, zum Beispiel aus einem Deep Link.

### Eine einzelne Demo zeigen

`ShowcaseDemoView` zeigt eine einzelne Demo und setzt ihren Navigationstitel:

```swift
struct ChartScreen: View {
    var body: some View {
        NavigationStack {
            ShowcaseDemoView(.chart3D)
        }
    }
}
```

### Den Katalog durchsuchen

`ShowcaseCatalog` enthält die Logik für Liste, Suche und Gruppierung hinter der Galerie. Eine
Suchanfrage passt zu einer Demo, wenn jedes Wort in ihrem Titel, ihrer Zusammenfassung oder ihrer
API-Liste vorkommt; Groß- und Kleinschreibung sowie diakritische Zeichen werden ignoriert:

```swift
let catalog = ShowcaseCatalog(platform: .iOS)
let matches = catalog.demos(matching: "glass button")   // [.glassButtons]
let sections = catalog.sections(matching: "symbol")     // one section: Charts, Symbols & Animation
let demo = catalog.demo(withID: "webView")              // .webView
```

### Die Hilfstypen hinter den Demos nutzen

Die Logik hinter einigen Demos ist öffentlich und durch Tests abgedeckt:

```swift
// What the web view demo accepts in its address bar.
WebAddress.url(from: "swift.org")              // https://swift.org
WebAddress.url(from: "javascript:alert(1)")    // nil

// The heights plotted by the 3D chart, always in -1...1.
SurfaceFunction.peak.height(x: 0, z: 0)        // 1.0
```

`RichTextFormatter` schaltet fett, kursiv, unterstrichen und durchgestrichen für den ausgewählten
Teil eines `AttributedString` um, so wie es die Buttons der Rich-Text-Demo tun.

### Hinweise zu einzelnen Demos

- **Foundation Models** braucht Apple Intelligence. Auf einem Gerät ohne Apple Intelligence, wenn
  sie ausgeschaltet ist oder während das Modell geladen wird, sagt die Demo, welcher Fall vorliegt,
  und deaktiviert den Button, der den Prompt sendet.
- **Tab-Bar-Zubehör**: `tabViewBottomAccessory(isEnabled:content:)` setzt iOS 26.1 voraus. Ab 26.1
  verwendet die Demo diese API; unter 26.0 fügt sie `tabViewBottomAccessory(content:)` hinzu oder
  lässt es weg.
- **WebView** lädt beim Erscheinen `https://www.swift.org` und braucht daher eine
  Netzwerkverbindung. Die Adressleiste akzeptiert nur `http`- und `https`-Adressen.

### Die Beispiel-App starten

Öffne `Examples/ShowcaseApp/ShowcaseApp.xcodeproj`, wähle das Schema `ShowcaseApp` und einen
Simulator mit iOS 26 oder **My Mac** und drücke **Run**. Das Projekt wird mit
[XcodeGen](https://github.com/yonaskolb/XcodeGen) aus `project.yml` erzeugt und bindet das Paket
aus diesem Repository über einen lokalen Pfad ein.

Übergib `-demo <id>` als Startargument, um eine Demo direkt zu öffnen, zum Beispiel
`-demo glassEffect`. `scripts/screenshots.sh` nutzt das, um die Bilder in `docs/images`
aufzunehmen.

Xcode 26.0 kann das Paket nicht bauen, weil die Tab-Bar-Demo eine API aus dem iOS-26.1-SDK

## Architektur

Das Paket hat ein einziges Bibliotheks-Target, `SwiftUIiOS26Showcase`:

- `Catalog/`: `ShowcaseDemo` hat pro Demo einen Case mit ihren Metadaten (Titel, Zusammenfassung,
  SF Symbol, Kategorie, APIs, Plattformen). `ShowcaseCatalog` filtert nach Plattform, sucht,
  gruppiert und findet Demos. Nichts in diesem Ordner hängt von SwiftUI-Views ab.
- `Gallery/`: die öffentlichen Views `ShowcaseGallery` und `ShowcaseDemoView`.
- `Demos/<Category>/`: eine interne View pro Demo. Logik, die keine View braucht, steckt in
  öffentlichen Hilfstypen (`WebAddress`, `RichTextFormatter`, `SurfaceFunction`), damit Tests sie
  abdecken können.
- `Support/`: `DemoPage`, das gemeinsame Layout mit Zusammenfassung, den Bedienelementen der Demo
  und der API-Liste.

Die Demo-Metadaten sind die einzige Quelle für die Zeilen der Galerie, die Suche und die Tabelle
oben; ein Test schlägt fehl, wenn README-Tabelle und Metadaten nicht übereinstimmen. Die Tests
laufen mit `swift test` unter macOS und mit `xcodebuild test` im iOS Simulator; CI führt beides
aus.

SwiftUI iOS 26 Showcase est un paquet Swift qui regroupe seize petits écrans SwiftUI, chacun
consacré à un groupe d’API apparues avec iOS 26 et macOS 26 : Liquid Glass, les nouveaux
modificateurs de barres et de défilement, l’édition de texte enrichi, la vue web native, les
graphiques 3D, les effets de tracé des SF Symbols, la macro `@Animatable` et le framework
Foundation Models, qui s’exécute sur l’appareil. Chaque écran propose des commandes pour essayer
les options de l’API et affiche la liste des symboles du SDK qu’il utilise. Le paquet s’adresse
aux développeurs qui veulent voir ces API fonctionner avant de les utiliser : vous pouvez lancer
toute la galerie ou intégrer un seul écran dans votre propre app.

## Points forts

- **16 démos dans 6 catégories** : Liquid Glass, barres et navigation, défilement et mise en
  page, texte et web, graphiques et symboles, et Apple Intelligence. 14 d’entre elles
  fonctionnent aussi sur macOS.
- **Galerie avec recherche** : `ShowcaseGallery` liste les démos disponibles sur la plateforme
  courante, et la recherche porte sur les titres, les résumés et les noms d’API.
- **Un seul écran à la fois** : `ShowcaseDemoView(.chart3D)` place une démo dans votre propre
  navigation.
- **Testé sur macOS et dans l’iOS Simulator** : des suites Swift Testing vérifient le catalogue,
  les types utilitaires et que le tableau des démos ci-dessous correspond au code. Un test de rendu
  vérifie que chaque démo dessine plus que son résumé et sa liste d’API, dans la mesure où
  `ImageRenderer` sait la dessiner : les deux démos basées sur `List` sont ignorées et, dans la démo
  **WebView**, le test voit les barres d’adresse et d’état, mais pas la `WebView` elle-même.
- **App d’exemple** : une app iOS et macOS dans [Examples/ShowcaseApp](Examples/ShowcaseApp), qui
  peut ouvrir n’importe quelle démo à partir d’un argument de lancement.

## Démarrage rapide

**1. Ajouter le paquet**

Dans Xcode, choisissez **File › Add Package Dependencies…** et saisissez l’URL du dépôt :

```text
https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git
```

Dans la même fenêtre, laissez **Dependency Rule** sur sa valeur par défaut, **Up to Next Major
Version**, à partir de `2.0.0` (l’ancienne version 1.0.0 est antérieure à ces démos). Cliquez
sur **Add Package**, choisissez la cible de votre app dans la colonne **Add to Target**, puis
cliquez de nouveau sur **Add Package**.

**2. Importer le module**

```swift
import SwiftUIiOS26Showcase
```

**3. L’utiliser**

Remplacez le contenu du fichier principal de votre app (celui marqué `@main`, nommé
`<YourApp>App.swift` dans un nouveau projet Xcode) par :

```swift
import SwiftUI
import SwiftUIiOS26Showcase

@main
struct DemoApp: App {
    var body: some Scene {
        WindowGroup {
            ShowcaseGallery()
        }
    }
}
```

Choisissez comme destination un simulateur d’iPhone sous iOS 26 ou **My Mac**, puis appuyez sur
**Run** (⌘R). L’app ouvre une liste des démos regroupées par catégorie ; choisissez-en une pour
l’essayer. Si Xcode signale que le paquet exige une plateforme plus récente, réglez
**Minimum Deployments** sur iOS 26 et macOS 26 dans l’onglet **General** de la cible.

## Installation

### Swift Package Manager

Dans Xcode, choisissez **File › Add Package Dependencies…** et saisissez l’URL du dépôt :

```text
https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git
```

Ou ajoutez-le aux `dependencies` de votre `Package.swift` :

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git", branch: "main")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "SwiftUIiOS26Showcase", package: "SwiftUI-iOS26-Showcase")
    ])
]
```

## Utilisation

### Afficher toute la galerie

`ShowcaseGallery` est une pile de navigation qui contient la liste, avec recherche, de toutes les
démos disponibles sur la plateforme courante. `ShowcaseGallery(initialDemo: .chart3D)` ouvre une
démo à l’affichage, par exemple depuis un lien profond.

### Afficher une seule démo

`ShowcaseDemoView` affiche une seule démo et définit son titre de navigation :

```swift
struct ChartScreen: View {
    var body: some View {
        NavigationStack {
            ShowcaseDemoView(.chart3D)
        }
    }
}
```

### Rechercher dans le catalogue

`ShowcaseCatalog` contient la logique de liste, de recherche et de regroupement de la galerie.
Une requête correspond à une démo quand chacun de ses mots apparaît dans le titre, le résumé ou la
liste d’API de la démo, sans tenir compte de la casse ni des accents :

```swift
let catalog = ShowcaseCatalog(platform: .iOS)
let matches = catalog.demos(matching: "glass button")   // [.glassButtons]
let sections = catalog.sections(matching: "symbol")     // one section: Charts, Symbols & Animation
let demo = catalog.demo(withID: "webView")              // .webView
```

### Utiliser les types utilitaires des démos

La logique de certaines démos est publique et couverte par des tests :

```swift
// What the web view demo accepts in its address bar.
WebAddress.url(from: "swift.org")              // https://swift.org
WebAddress.url(from: "javascript:alert(1)")    // nil

// The heights plotted by the 3D chart, always in -1...1.
SurfaceFunction.peak.height(x: 0, z: 0)        // 1.0
```

`RichTextFormatter` active ou désactive le gras, l’italique, le soulignement et le barré sur la
partie sélectionnée d’une `AttributedString`, comme le font les boutons de la démo de texte
enrichi.

### Remarques sur certaines démos

- **Foundation Models** nécessite Apple Intelligence. Sur un appareil qui ne la prend pas en
  charge, lorsqu’elle est désactivée ou pendant le téléchargement du modèle, la démo indique
  lequel de ces cas s’applique et désactive le bouton qui envoie le prompt.
- **Accessoire de la barre d’onglets** : `tabViewBottomAccessory(isEnabled:content:)` nécessite
  iOS 26.1. À partir de 26.1, la démo l’utilise ; sous 26.0, elle ajoute ou retire
  `tabViewBottomAccessory(content:)`.
- **WebView** charge `https://www.swift.org` à l’affichage et nécessite donc une connexion réseau.
  La barre d’adresse n’accepte que les adresses `http` et `https`.

### Lancer l’app d’exemple

Ouvrez `Examples/ShowcaseApp/ShowcaseApp.xcodeproj`, choisissez le schéma `ShowcaseApp` et un
simulateur iOS 26 ou **My Mac**, puis appuyez sur **Run**. Le projet est généré par
[XcodeGen](https://github.com/yonaskolb/XcodeGen) à partir de `project.yml` et utilise le paquet
de ce dépôt par un chemin local.

Passez `-demo <id>` comme argument de lancement pour ouvrir directement une démo, par exemple
`-demo glassEffect`. `scripts/screenshots.sh` s’en sert pour capturer les images de `docs/images`.

## Architecture

Le paquet comporte une seule cible de bibliothèque, `SwiftUIiOS26Showcase` :

- `Catalog/` : `ShowcaseDemo` a un cas par démo avec ses métadonnées (titre, résumé, SF Symbol,
  catégorie, API, plateformes). `ShowcaseCatalog` filtre par plateforme, recherche, regroupe et
  retrouve les démos. Rien dans ce dossier ne dépend des vues SwiftUI.
- `Gallery/` : les vues publiques, `ShowcaseGallery` et `ShowcaseDemoView`.
- `Demos/<Category>/` : une vue interne par démo. La logique qui n’a pas besoin de vue se trouve
  dans des types utilitaires publics (`WebAddress`, `RichTextFormatter`, `SurfaceFunction`) pour
  que les tests puissent la couvrir.
- `Support/` : `DemoPage`, la mise en page commune avec le résumé, les commandes de la démo et la
  liste des API.

Les métadonnées des démos sont la seule source des lignes de la galerie, de la recherche et du
tableau ci-dessus ; un test échoue si le tableau du README et les métadonnées ne concordent pas.
Les tests s’exécutent avec `swift test` sur macOS et avec `xcodebuild test` dans l’iOS Simulator ;
la CI lance les deux.

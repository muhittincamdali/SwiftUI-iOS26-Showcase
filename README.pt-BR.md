SwiftUI iOS 26 Showcase é um pacote Swift com dezesseis telas pequenas em SwiftUI, cada uma
dedicada a um grupo de APIs novas no iOS 26 e no macOS 26: Liquid Glass, os novos modificadores
de barras e de rolagem, a edição de texto rico, a web view nativa, os gráficos 3D, os efeitos de
desenho de SF Symbols, a macro `@Animatable` e o framework Foundation Models, que roda no próprio
dispositivo. Cada tela tem controles para experimentar as opções da API e lista os símbolos do
SDK que usa. O pacote é para desenvolvedores que querem ver essas APIs funcionando antes de
usá-las: você pode rodar a galeria inteira ou colocar uma única tela no seu próprio app.

## Destaques

- **16 demos em 6 categorias**: Liquid Glass, barras e navegação, rolagem e layout, texto e web,
  gráficos e símbolos, e Apple Intelligence. 14 delas também rodam no macOS.
- **Galeria com busca**: `ShowcaseGallery` lista as demos disponíveis na plataforma atual, e a
  busca procura em títulos, resumos e nomes de APIs.
- **Uma tela de cada vez**: `ShowcaseDemoView(.chart3D)` coloca uma única demo na sua própria
  navegação.
- **Testado no macOS e no iOS Simulator**: suítes de Swift Testing verificam o catálogo, os tipos
  auxiliares e se a tabela de demos abaixo corresponde ao código. Um teste de renderização verifica
  se cada demo desenha mais do que o resumo e a lista de APIs, até onde o `ImageRenderer` consegue
  desenhá-la: as duas demos baseadas em `List` são ignoradas e, na demo de **WebView**, o teste vê
  as barras de endereço e de status, mas não a `WebView` em si.
- **App de exemplo**: um app para iOS e macOS em [Examples/ShowcaseApp](Examples/ShowcaseApp) que
  abre qualquer demo a partir de um argumento de inicialização.

## Início rápido

**1. Adicione o pacote**

No Xcode, escolha **File › Add Package Dependencies…** e informe a URL do repositório:

```text
https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git
```

Na mesma janela, deixe **Dependency Rule** no valor padrão, **Up to Next Major Version**, a
partir de `2.0.0` (a versão anterior, 1.0.0, é anterior a estas demos). Clique em **Add Package**,
escolha o target do seu app na coluna **Add to Target** e clique em **Add Package** de novo.

**2. Importe o módulo**

```swift
import SwiftUIiOS26Showcase
```

**3. Use**

Substitua o conteúdo do arquivo principal do seu app (o marcado com `@main`, que em um projeto
novo do Xcode se chama `<YourApp>App.swift`) por:

```swift
import SwiftUI
import SwiftUIiOS26Showcase

@main
struct DemoApp: App {
    var body: some Scene {
        WindowGroup {
            ShowcaseGallery()
        }
    }
}
```

Escolha como destino um simulador de iPhone com iOS 26 ou **My Mac** e pressione **Run** (⌘R).
O app abre uma lista das demos agrupadas por categoria; escolha uma para experimentar. Se o Xcode
avisar que o pacote precisa de uma plataforma mais recente, defina **Minimum Deployments** como
iOS 26 e macOS 26 na aba **General** do target.

## Instalação

### Swift Package Manager

No Xcode, escolha **File › Add Package Dependencies…** e informe a URL do repositório:

```text
https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git
```

Ou adicione-o às `dependencies` do seu `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/SwiftUI-iOS26-Showcase.git", branch: "main")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "SwiftUIiOS26Showcase", package: "SwiftUI-iOS26-Showcase")
    ])
]
```

## Uso

### Mostrar a galeria inteira

`ShowcaseGallery` é uma pilha de navegação com uma lista pesquisável de todas as demos disponíveis
na plataforma atual. `ShowcaseGallery(initialDemo: .chart3D)` abre uma demo ao aparecer, por
exemplo a partir de um deep link.

### Mostrar uma única demo

`ShowcaseDemoView` mostra uma única demo e define o título de navegação dela:

```swift
struct ChartScreen: View {
    var body: some View {
        NavigationStack {
            ShowcaseDemoView(.chart3D)
        }
    }
}
```

### Buscar no catálogo

`ShowcaseCatalog` reúne a lógica de lista, busca e agrupamento por trás da galeria. Uma consulta
corresponde a uma demo quando cada palavra aparece no título, no resumo ou na lista de APIs da
demo, sem diferenciar maiúsculas, minúsculas e acentos:

```swift
let catalog = ShowcaseCatalog(platform: .iOS)
let matches = catalog.demos(matching: "glass button")   // [.glassButtons]
let sections = catalog.sections(matching: "symbol")     // one section: Charts, Symbols & Animation
let demo = catalog.demo(withID: "webView")              // .webView
```

### Usar os tipos auxiliares das demos

A lógica por trás de algumas demos é pública e coberta por testes:

```swift
// What the web view demo accepts in its address bar.
WebAddress.url(from: "swift.org")              // https://swift.org
WebAddress.url(from: "javascript:alert(1)")    // nil

// The heights plotted by the 3D chart, always in -1...1.
SurfaceFunction.peak.height(x: 0, z: 0)        // 1.0
```

`RichTextFormatter` liga e desliga negrito, itálico, sublinhado e tachado na parte selecionada de
uma `AttributedString`, como fazem os botões da demo de texto rico.

### Observações sobre algumas demos

- **Foundation Models** precisa da Apple Intelligence. Em um dispositivo sem ela, com ela
  desativada ou enquanto o modelo é baixado, a demo informa qual desses casos se aplica e
  desativa o botão que envia o prompt.
- **Acessório da barra de abas**: `tabViewBottomAccessory(isEnabled:content:)` precisa do
  iOS 26.1. No 26.1 e posteriores a demo usa essa API; no 26.0, ela adiciona ou remove
  `tabViewBottomAccessory(content:)`.
- **WebView** carrega `https://www.swift.org` ao aparecer, por isso precisa de conexão com a
  internet. A barra de endereço aceita apenas endereços `http` e `https`.

### Rodar o app de exemplo

Abra `Examples/ShowcaseApp/ShowcaseApp.xcodeproj`, escolha o esquema `ShowcaseApp` e um simulador
com iOS 26 ou **My Mac**, e pressione **Run**. O projeto é gerado pelo
[XcodeGen](https://github.com/yonaskolb/XcodeGen) a partir de `project.yml` e usa o pacote deste
repositório por um caminho local.

Passe `-demo <id>` como argumento de inicialização para abrir uma demo diretamente, por exemplo
`-demo glassEffect`. O `scripts/screenshots.sh` usa isso para capturar as imagens em
`docs/images`.

## Arquitetura

O pacote tem um único target de biblioteca, `SwiftUIiOS26Showcase`:

- `Catalog/`: `ShowcaseDemo` tem um case por demo com os metadados dela (título, resumo,
  SF Symbol, categoria, APIs, plataformas). `ShowcaseCatalog` filtra por plataforma, busca,
  agrupa e localiza demos. Nada nesta pasta depende de views do SwiftUI.
- `Gallery/`: as views públicas, `ShowcaseGallery` e `ShowcaseDemoView`.
- `Demos/<Category>/`: uma view interna por demo. A lógica que não precisa de view fica em tipos
  auxiliares públicos (`WebAddress`, `RichTextFormatter`, `SurfaceFunction`) para que os testes
  possam cobri-la.
- `Support/`: `DemoPage`, o layout compartilhado com o resumo, os controles da demo e a lista de
  APIs.

Os metadados das demos são a única fonte das linhas da galeria, da busca e da tabela acima; um
teste falha quando a tabela do README e os metadados não batem. Os testes rodam com `swift test`
no macOS e com `xcodebuild test` no iOS Simulator; a CI roda os dois.
